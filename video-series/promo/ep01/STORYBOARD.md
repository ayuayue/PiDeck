# PiDeck 宣传片 EP01 — 分镜（v4 · 五会话并行 + 三段知识卡版）

## 为什么有 v4

v3 证明了卖点方向对（**5 个会话各占一个 Tab，同时在跑**），但节奏太赶：40s 要塞完
「并行 → 分屏 → 终端/Git → 尾板」，中段只能一掠而过，看不出「会话是 Tab」这件事的细节。

v4 做了三件事：

1. **拉长到 79.6s**，把「5 个 Tab 各自在跑」这一拍从 5 秒扩到 **21.5s**（16.0–37.5），
   中间依次给标签栏特写、把 Tab 拖到边上分屏、终端+Git 同会话三段可读的证据。
2. **结尾加三段知识卡**（45.6–72.4）：Pi vs DSH 双后端 / 一个窗口 vs 五个终端 /
   11 种来源导入。每张卡是**在同一个窗口形状上换内容**（One shape never cut 的延伸）。
3. **数字页**（67.8–72.4）后接收束页（72.8–75.4），再塌回 tile 做尾板。

冷开场也重做成**真产品 logo**：PiDeck 侧栏在用的 pi-tui 三色像素标（绿/黄/红），
它本身就是一个 4×4 像素栅格——「这张会长成窗口的图」在字面上成立。

## 关键实现约定（改动画前必读）

1. **相机是 log-zoom**：`#world{transform:translate(960,540) scale(z) translate(-cx,-cy)}`，
   `w2s(px,py,t)` 把世界坐标换到屏幕坐标（拖影、被拖拽 Tab 这类屏幕定位元素必须用它）。
2. **`stepR` 单调**：「淡回来」不能靠反向弹簧，只能 `f(x) * (1 - stepR(...))` 相乘。
3. **形变弹簧 ≠ 转场弹簧**：w/h/radius 用 `{w:5.4,z:0.78}`；用 `SP(0.72)` 会让生长在 0.3s 内跳完。
4. **知识卡是屏幕定位**（`.card{left:0;top:0;width:1920px}`，在 `#world` 之外），
   所以窗口退场时必须**连 `#shape` 一起淡**（`#shape` 自带 `background:#171717`）。
5. **绝不 `will-change` 相机缩放链上的元素**（文字会糊）。
6. **`<i>` 之类的行内元素必须给显式尺寸 + `display:block`**，否则全 0×0（42 个色块曾因此整片不可见）。

## 七条决策

1. **用暗色做片**：PiDeck 实测暗色面板底 `#171717` 占 73%，和舞台 `#0d0d0e` 几乎无缝；浅色截图放进暗底会像贴纸。
2. **UI 全部 HTML 重建，不贴图**：`docs/images/` 的截图久未维护（用户明确要求改用 CUA 现抓），
   且贴图无法做形变与逐拍动画。本片所有界面元素都按 CUA 实测的几何/配色/文案用 DOM 复刻。
3. **冷开场用 pi-tui 三色像素标而不是银色 π**：它是 4×4 栅格，能自然「长成」窗口，
   把 One shape never cut 变成字面成立；银色 π 留给尾板 wordmark。
4. **79.6s 而不是 40s**：并行是本片唯一卖点，值得给它 27% 的片长；知识卡让片子有「信息密度」而不只是好看。
5. **120fps 渲染 + ffmpeg 运动模糊降 60fps**：实测 headless 截图吞吐 ≈0.23s/帧且与并发无关，
   120fps 渲完再用 `tmix=frames=2` 补运动模糊，比直接 60fps 采样更顺。
6. **字幕全部中文互补句**，不复述卡片标题（卡片标题已是大字，重复就变噪音）。
7. **数字页用真实量级**（1714 providers / 11 种导入来源），不编造更「整」的数字。
