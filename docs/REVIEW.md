# 评审面板

桌面端的「评审」面板按项目和仓库读取 GitHub CLI 的拉取请求与议题。它不保存 GitHub 凭据，凭据仍由运行目标上的 `gh` 管理。

## 使用流程

1. 先在侧栏添加或选中一个项目，再打开「评审」。顶部的「项目」选择器可以切换已经导入的项目。
2. 如果项目目录本身是 Git 仓库，面板直接使用它；如果项目是一个包含多个仓库的目录，面板会发现其中直接包含 `.git` 的子仓库，并在「仓库」菜单中列出它们。切换项目或仓库后，列表会重新读取。
3. 选择「拉取请求」或「议题」，按打开、已关闭或全部筛选，也可以按标题、编号和标签搜索；需要更多结果时使用「加载更多」。
4. 打开条目后可以查看描述、讨论、检查、改动文件和完整补丁，并执行评论、提交评审、合并、关闭或重新打开等操作。

项目和仓库各自保留当前的列表筛选、搜索词、分页数量、详情状态以及未发送的评论草稿。切换回来时会恢复对应内容，避免不同项目或仓库之间串入草稿和迟到的请求结果。这些界面状态只保存在本次应用运行期间；GitHub 上的条目和已提交操作仍以 GitHub 为准。

## 加载与导航

- 首次读取、切换筛选以及读取详情或补丁时会显示加载占位；刷新已有内容时保留当前页面，并在顶部显示读取状态。
- 列表、详情和补丁之间使用短过渡，遵循应用「减少动效」和系统的减少动态效果设置。刷新详情不会替换评论输入框，已输入的内容和焦点可以继续保留。
- 评论、评审、合并和状态变更会显示对应操作的等待与结果，等待期间阻止重复提交。读取失败可以重试，提交失败会保留评论草稿。
- 补丁页提供返回、刷新与失败重试；同一条目的补丁再次打开时优先使用本次运行内的缓存。只有成功读取的非空补丁可以复制。`Esc` 从补丁返回详情，再从详情返回列表。

## AI 评估

详情页的「AI 评估」会创建一条新的 pi 会话，并把当前条目的 `gh pr view` / `gh pr diff` 或 `gh issue view` 读取要求交给它。会话使用当前选中的仓库目录和目标端运行；项目目录下选择的子仓库会自动登记为独立项目，这样后续会话仍归属于正确的代码目录。

## 使用前提

- 运行评审命令的本机、WSL 或 SSH 目标需要安装 GitHub CLI `gh`。
- 在对应目标上执行 `gh auth login`，让 CLI 自己持有 GitHub 凭据。
- 如果面板提示未安装或未登录，完成对应设置后点「刷新」重试。
- 评论、评审结论、合并、关闭和重新打开会改变 GitHub 上的共享数据。发送评论前请核对内容；提交评审、合并、关闭和重新打开会先显示确认提示。
