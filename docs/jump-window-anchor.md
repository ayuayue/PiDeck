# 锚定窗口的状态约束

跳转把渲染窗口从「尾窗」换成「锚定窗」后，`autoScroll` 不能再由滚动位置推出。

## 一、为什么二分不够

尾窗下「看到底」与「会话到底」是同一件事，所以贴底判定只有一条链（`SessionMessageTimeline:489-490`）。
锚定窗下两者分开：窗口底在会话中间。此时按「滚到底 = autoScroll = true」判，两条结果都坏：

| 判法 | 结果 |
| --- | --- |
| 判成 autoScroll = true | 清锚点 → 视图从第 100 轮直接跳到会话末尾（用户看到「跳到别处了」） |
| 不判成 | 「回底」按钮常亮、新消息不跟随（用户以为又卡住了） |

## 二、约束（一条）

> `autoScroll` 只由三种动作设置，**不由滚动位置推出**：
> 点「回底」按钮 / 发消息 / 窗口末轮真的等于会话末轮。

| 状态 | autoScroll | startRun |
| --- | --- | --- |
| 尾窗（贴底） | true | undefined |
| 锚定窗中间 | false | 目标轮 |
| 锚定窗滚到**窗口底** | false（不变） | 不变 |
| 锚定窗 + 点回底 | true | undefined（清） |
| 锚定窗 + 发消息 | true | undefined（清，新消息必须可见） |

## 三、判据（都能红）

```
跳转到第 100 轮 -> 滚到窗口底 -> autoScroll 仍为 false 且 startRun 未变
同上 -> 点回底 -> startRun === undefined 且窗口末轮 === 会话末轮
跳转到第 100 轮 -> 发一条 -> startRun === undefined
```

## 四、暂不做的代价（明写，不当已验证）

锚定窗里继续下滚不滑窗（`startRun += k`），用户会撞墙。
比「一跳就回末尾」轻，也不会误报；滑窗下一轮再做。

## 五、这次改动会放大的三处（都在未验证清单里）

| 处 | 现在 | 改动后 |
| --- | --- | --- |
| 切会话恢复 | `SessionScrollAnchor` 只有 `windowTurns`，没有 `startRun` | 恢复后锚点行不在窗口 → 降级到底部 |
| 「显示更早」 | 数据 prepend，不动窗口 | 锚定窗下 prepend 不改挂载内容 → 点了没反应 |
| 分屏同会话 | 两栏共享锚点，只差高度 | 起点互相覆盖 → 整段错 |

## 六、锚点是 run id，不是下标

startRun 是**下标**，而 session-history-atoms.ts:327 的 prepend 是「新页插在头部」：
所有 run 的下标整体后移 Δ。

所以「显示更早」在锚定窗下是两步，不是一步：

    startRun += Δ        补偿头部插入（保持窗口内容不动）
    startRun -= 页轮数     这才真的往前看（clamp >= 0）
    净效果：startRun + Δ - pageTurns

漏掉第一步的症状很具体：用户点「显示更早」，界面**不往前、反而往回跳 Δ 轮**，目标行掉出窗口 ——
比死按钮更难解释（死按钮至少看起来像没做）。

### 定法：真值存 id，下标是派生值

    锚点   { anchoredRunId: string }  +  缓存的 startRun（派生，不作真值）
    runs 变（prepend / 新轮到达）时用 anchoredRunId 重算一次 startRun

代价：每次数据变多算一次 **O(当前窗口)** 的查找（runIndexOfMessage，b75835684），不是每帧。
收益：Δ 补偿不再是「调用方记得」的记忆点 —— 它是派生的一部分，忘了也错不了。

不采用「靠调用方做 Δ 补偿」的理由：那是这条规则里唯一的记忆点，而记忆点正是今晚反复出错的东西。

### 判据（都能红）

    锚定到第 k 轮 -> prepend 一页 -> 窗口首个 run 的 id 不变
    同一次操作后 -> 窗口轮数不变（滑窗只移起点，不扩窗）

第二条防「顺手把拼好的页全挂上」—— 那是扩窗，O(1) 又没了。
