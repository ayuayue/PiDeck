# 微信与飞书集成

本文说明桌面版「集成与自动化」中微信、飞书的实际能力、会话入口和验证范围。

## 微信 iLink

1. 在设置 → 集成与自动化 → 微信 iLink 中选择「扫码登录微信」，使用自己的微信扫码确认；若出现验证码，在应用里填写手机显示的验证码。
2. 打开准备接收消息的应用内会话，先信任其项目。在会话标签、侧栏会话的右键菜单或会话的更多菜单中，选择「微信 iLink → 绑定当前会话」。右键后台标签会绑定该标签对应的会话，不会切换当前会话。
3. 回到微信设置，开启「接收微信消息」。设置页不执行会话绑定。
4. 用登录账号给微信中的机器人发送私聊文字。文字或已有转写文本的语音会提交到已绑定会话；轮次结束后，回答发回这条私聊。权限确认仍在 PiDeck 内进行。

一个登录连接只绑定一个会话。接收中切换绑定目标会重启消息接收；有微信回答待返回时暂不允许重新绑定。

当前限制：

- 只接受扫码账号的私聊，不接受其他账号、群聊或机器人消息。
- 不接收图片、文件等媒体，也不自行转写音频。输入最多 24 KiB，返回文字最多 3500 字，超出后截断。
- 会话运行、加载历史、停止、重试或加载附件期间不提交新消息，会向微信回复稍后重发的提示。
- 绑定目标不存在、为只读外部会话或项目未受信任时拒绝提交。
- 二维码过期后需手动重新登录；登录失效错误 `-14` 会停止接收，需重新登录。
- 登录凭据、绑定会话、接收游标及最近 256 条消息 ID 保存在应用数据目录的 `wechat/connection.yaml`，通过临时文件加重命名写入。退出登录会清空连接。

请求身份依据腾讯当前客户端协议：`iLink-App-Id=bot`，应用版本头按 `0x00MMNNPP` 编码；`channel_version` 使用兼容的 `3.0.0` 前缀并附带 PiDeck 自身版本，`bot_agent` 保留 `PiDeck-V2`。二维码状态 GET 不携带 Bot 鉴权头。

## 飞书

飞书目前由两个独立能力组成：

| 能力 | 配置与实际行为 |
| --- | --- |
| 完成通知 | 飞书群自定义机器人的 Webhook，可选签名密钥。发送会话标题、状态与首行摘要。 |
| 接收群消息 | 飞书应用机器人的 HTTP 事件回调，使用 Verification Token 校验；订阅 `im.message.receive_v1`，接收用户的文本消息。 |
| 把回答发回群 | 轮次结果发送到上面配置的自定义机器人 Webhook，最多取回答首行的 1500 字。 |

「接收群消息」需要另外配置飞书应用及其消息权限；只创建群自定义机器人并填写 Webhook，无法接收消息。

接收配置步骤：

1. 在「手机与远程」启用桌面 HTTP 服务；飞书回调复用该服务的 `/api/feishu` 路由。通过自己的 HTTPS 入口让飞书能够访问该路径。
2. 在「集成与自动化」开启「接收群消息」，填写飞书应用提供的 Verification Token。
3. 在飞书开放平台配置 HTTP 回调地址并订阅消息事件。应用响应 URL 验证的 challenge，拒绝不匹配的 Token 和超过 1 MiB 的请求。
4. 收到消息时，PiDeck 为每个来源聊天自动建立独立的内置对话。用户无需在设置页关联会话；当前打开的项目不会决定消息去向。
5. 如需回发，配置该来源群的自定义机器人 Webhook，并开启「把回答发回群」。「发一条」只验证 Webhook 发送，不验证事件订阅、模型运行或整条收发链路。

当前限制：

- Webhook 固定对应一个群，不会按收到的 `chat_id` 向原聊天调用飞书应用消息 API。开启回发时，应只接入与此 Webhook 相同的群；不要把它当作多群或私聊机器人。
- 不支持飞书应用的 WebSocket 长连接，也未实现加密回调解密。
- 仅处理文字。非消息事件、机器人消息和重复的 `message_id` 不再触发轮次。
- 来源聊天与内置会话的对应关系、最近 256 个消息 ID 仅保留在当前进程。应用重启后，下一条消息会新建来源对话。
- 目标会话运行或暂不可提交时，新消息不会覆盖已有轮次，应用显示提示；本次消息不会排队，需稍后重发。
- 同时启用完成通知和回答回发时，来自飞书的同一轮只回发一条结果。发送失败在应用内显示错误；只有 HTTP 成功且飞书返回明确的成功业务码才判定发送成功。

## 已验证与未验证

本次验证使用临时数据目录、固定协议样本和本地模拟 HTTP 服务，不读取真实账号凭据，也不调用外部模型。已覆盖：

- 微信二维码登录成功、过期及不可信回调主机；登录请求头、状态轮询和凭据保存。
- 微信私聊归属校验、重复消息、会话不可提交时的拒绝，以及消息提交后带原接收人和上下文回发。
- 飞书签名、发送响应判定、回调 Token 与 challenge、请求大小、用户事件筛选、重复消息、来源会话隔离及一次性回发。
- Windows 原生界面实际打开会话菜单并绑定后台标签；设置页没有绑定按钮。

复现命令（只运行相关包）：

```sh
go test ./internal/workbench -run '^(Test.*Feishu.*|Test.*Wechat.*)$' -count=1 -timeout=90s
go tool nsgo test -target windows_x64 -run '^(TestWechatSettingsHasNoSessionBinding|TestWechatBindingLivesInSessionMenu)$' -timeout 30s ./internal/workbench
```

原生截图位于 `internal/workbench/.nsgo/test/screenshots/windows/integrations/`。

**尚未进行真实微信扫码、真实飞书群收发及外部模型完整联调，不能据此宣称真实账号端到端验收通过。** 真实验收应分别确认扫码与验证码、应用重启后的恢复、连续两轮对话、会话忙时重发、权限审批和实际群内只出现一条回复。飞书还需在其控制台确认事件订阅和权限已生效。
