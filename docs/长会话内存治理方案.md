# 长会话内存治理方案（轮次化历史模型）

> 适用范围：超长 Pi 会话（几十 MB JSONL、数百轮对话）下的主进程内存、文件读取与渲染层 DOM 治理。
> 本文档描述当前实现（2026-09 轮次协议定案，常量值以代码为准），改动时请同步更新「常量一览」。

## 1. 背景与目标

超长会话在旧模型下存在四类问题：

| 问题 | 旧行为 | 后果 |
|---|---|---|
| 主进程消息数组无界增长 | 只在 `loadMessages` 时 trim 一次（40 轮） | 长会话运行中数组持续追加，内存线性膨胀 |
| 大文件全量解析 | 大会话激活直接 `get_messages` 全量 RPC / 全文件 `readFile` | 几十 MB 会话打开卡顿十几秒 |
| 渲染层 DOM 全量挂载 | 100 条分页器 + 全部消息常驻 atom，折叠内容 CSS 隐藏不卸载 | 长会话渲染/滚动卡顿 |
| 历史翻页坐标错乱 | 渲染层与文件各算各的下标 | 编辑/删除/重发命中错误轮次 |

**目标**：任何长度的会话，运行期内存、文件 IO、渲染 DOM 都有**常数上界**；历史可随时按「完整轮次」回溯，不截断对话。

## 1.5 链路加载量速查（2026-09 轮次协议）

**点开一个会话（启动 agent）后，各层实际加载多少：**

| 层 | 加载内容 | 数量 | 说明 |
|---|---|---|---|
| 磁盘 JSONL | 全量（真相源） | = 文件大小 | 只有 pi 进程写；PiDeck 从不驻留全文 |
| pi 子进程 | 全量加载入内存（pi 自身行为） | = 文件大小 | PiDeck 不干预；但禁止向 pi 取历史（get_messages 单行 JSON 冻窗） |
| 主进程 AgentManager | 尾部 12 轮（`MAX_RUNTIME_CACHE_TURNS`） | 12 轮 | `agent_settled` 后 trim；agent 闲置释放后整体清空 |
| 主进程 SessionHistoryReader | 索引元数据（每行 offset/长度） | ≤32 会话 LRU | 不含正文；正文按 offset 读盘 |
| 主进程预取缓存 | 下一页消息（后台备好） | 2 页 LRU | 连续上滚零文件 IO |
| 渲染层 atom | 尾部 9 轮窗口段 + 翻页前缀 | 9 轮起步 | 翻页 +3 轮/页；8 会话 LRU |
| DOM 挂载 | 尾部 3 轮起步（折叠头+最终回答） | 3 轮起步 | 上滚按 3 轮 cohort 渐进扩；历史轮折叠即卸载 |

**轮次定义（发言权周期）**：一轮 = 用户连续发言（可连发多条 user）→ AI 回应周期（assistant/tool/thinking），直到下一条用户发言。连发 user 只有第一条算轮起点；纯 user 无回复整段算 1 轮。页边界永远对齐完整轮，任何路径不切断一轮。

**两条读取路径（同一协议）**：

| | 路线 A：仅打开 Tab 浏览（无 agent） | 路线 B：启动 agent 后 |
|---|---|---|
| 首开 | `readRecordMessagePage(sessionId, undefined, 9)` — 尾部 9 轮 | 主进程 loadMessages(12) → flush 9 轮窗口 |
| 翻页 | `readRecordMessagePage(sessionId, nextBefore, 3)` | 同左（`tryReadRuntimeTurnPage` 先查 12 轮缓存命中） |
| 数据来源 | SessionHistoryReader 索引 → 按 offset 读盘 | 主进程内存 → 索引回退 |
| 预取 | 主进程后台预取下一页（2 页 LRU） | 主进程缓存命中即免 IO |

**点开 N 个会话（纯浏览未启动 agent）**：磁盘 = N 个全量文件；主进程 = 0（无 agent，无 messages）；索引 = N 个元数据（≤32）；渲染层 atom = N 个条目 × 9 轮起步（8 会话 LRU 滚动）；DOM = 仅当前可见会话 3 轮起步。

## 2. 总体架构：三级缓存链路

```
渲染层 atom（最近 8 会话 LRU，尾部 9 轮窗口段 + 临时 history 前缀）
        │  翻历史：readRecordMessagePage(unit:"turn", 3 轮/页) + 主进程预取下一页
        ▼
主进程 AgentManager 内存缓存（最近 12 轮，agent_settled 后裁剪）
        │  未命中：readSessionDisplayTurnPage
        ▼
SessionHistoryReader（JSONL 全量展示索引 + 增量 append + 2 页预取缓存）
```

- **数量模型（2026-09 轮次协议定案）**：DOM 3 / atom 9 / main 12。渲染层 DOM 只挂载尾部 3 轮，
  atom 常驻最近 9 轮窗口段（DOM 扩窗与翻页共用 3 轮 cohort），主进程缓存 12 轮 = atom 9 轮 + 1 页 3 轮缓存命中余量。
- **轮次为主（2026-09 统一）**：所有路径的页大小都以「轮」（turns）为单位——disk 首开 9 轮、disk/runtime 翻页均为 3 轮；
  不再有「按消息条数（100 条）」与「按条目预算（200）」的旁路单位（见 §4.3 / §5.2）。
- **数据链路单一**：`renderer atom → AgentManager.messages → SessionHistoryReader / JSONL`，渲染层不直接读文件。
- **回退总是安全**：缓存未命中/不活跃会话/会话已切换 → 文件路径，行为与历史浏览一致。

## 3. 主进程内存预算

### 3.1 运行期缓存：最近 12 轮硬上限

- `AgentManager.MAX_RUNTIME_CACHE_TURNS = 12`：`agent_settled`（一轮结束）与 `get_state` 兜底确认空闲时调用 `trimRuntimeCache()` 裁剪。
- 裁剪按 turn 起点（`turnTrimStartIndex`，发言权周期语义，见 §1.5），保留尾部 12 轮 + 头部系统摘要卡片（compaction/branchSummary 不占轮次、裁剪后重新 prepend）。
- 裁剪后重算激活显示窗口（尾部 9 轮）并**全量 flush**——头部整轮被裁，增量下标空间失效，渲染层以窗口化全量校准。
- `AgentManager.MAX_HISTORY_LOAD_TURNS = 12`：大会话首次激活从文件尾部直读（`readRecentMessagesFromSessionFile`）时最多取 12 轮，绕过 `get_messages` 全量 RPC。

### 3.2 激活显示窗口：尾部 9 轮

- `AgentManager.DISPLAY_WINDOW_TURNS = 9`：flush 载荷只下发窗口段 `[windowStart..]`（`buildMessageFlushPayload`），窗口前系统摘要卡片一并 prepend。每次 flush 先把窗口起点对齐到尾部 9 轮（新轮进入尾部时窗口右移，滑出轮随 `slideOut` 下发并入渲染层 history 前缀），保证新会话在 12 轮以内也不会把整个数组发进 atom。
- `totalLength` 恒为数组全长，渲染层用「窗口偏移 + 长度」校验增量合并；不连续即丢弃，等下一次全量校准。

### 3.3 缓存头部偏移：`messageHeadOffsetByAgent`

- 记录运行期缓存头部在**文件消息下标空间**的位置，由 `loadMessages`（entryId 路径 = 被裁角色消息数；skipEntries 路径 = 文件活动消息数 − 缓存角色消息数，best-effort）与 `trimRuntimeCache`（按被裁角色消息数递增，**卡片不计入**）维护。
- 用途：无 entryId 的窗口（大历史 skipEntries 路径）需要数值游标补历史时，把窗口首条消息换算为文件下标（见 §6）。

## 4. 文件索引与分页（SessionHistoryReader）

### 4.1 全量展示索引

每个会话文件构建一份 `SessionDisplayIndex`（`getSessionDisplayIndex`）：

```
entries              Map<entryId, {offset, byteLength, role, messageId, ...}>  全量条目（含非活跃分支）
activeBranch         沿 parentId 从最后条目回溯的活动分支（含 compaction 等非消息条目）
activeMessageEntries 活动分支中的消息条目（分页/轮次计算用）
endsWithNewline      构建时文件是否以完整行结尾（增量 append 的前置条件）
size / mtimeMs       文件版本（indexVersion 来源）
```

- 索引 LRU 上限 `SESSION_DISPLAY_INDEX_LIMIT = 32`（`trimDisplayIndexCache`）。
- 单页轮次上限 `MAX_TURN_PAGE_SIZE = 10`（防恶意参数撑爆 IPC）。
- 索引只存元数据（offset/长度/类型），**不含正文**；正文按 offset `read()` 按需读取。

### 4.2 增量 append（带探针校验）

- 文件变大且旧索引以完整行结尾 → `appendIndexFromTail` 只读新增字节并追加条目。
- **前置探针**：增量前在已打开的句柄内抽查旧索引首/末条目的 `offset/byteLength` 仍能解析出相同 id。`SessionFileEditor.atomicReplace`（temp + rename 整文件重写）导致增长时，旧偏移必然错位 → 探针失败 → 回退**全量重建**。
- 纯 append 保证 `[0, oldSize)` 字节不变 → 探针通过 → 增量效率保留。
- 已知残余风险（文档化）：多次编辑且长度互补、恰好保持末条目偏移不变的重写可绕过探针；完全精确需整前缀哈希（O(oldSize)），违背增量目的，不采用。

### 4.3 轮次分页协议

`readSessionDisplayTurnPage` 返回：

```
messages           页内消息（convertMessages 投影，带 entryId）
total              文件活动分支消息条目数
nextBefore         下一页游标（文件绝对消息下标；到顶为 null）
nextBeforeEntryId  页最旧条目的 entryId（跨下标空间稳定锚点）
indexVersion       `${mtimeMs}:${size}`（渲染层检测压缩/外部改写，变化即丢弃历史前缀）
```

- 页边界用 `findTurnPageStart` 按 **turn 起点**（发言权周期）对齐完整轮次；任何路径都不按固定消息数切断一轮（2026-09 已删除字节预算，单轮再大也整轮返回）。
  - **2026-09 轮次语义**：turn 起点 = `role==="user"` 且「跳过中间杂项（system/error/卡片）后前一条真实消息不是 user」——连发 user 只有第一条为起点，其余并入同一轮；纯 user 无回复的会话整段算 1 轮（发言权未交还）。
- 压缩会话（`hasCompaction`）走全量读取 + 切片（归档语义未游标化前），有 50MiB fixture 覆盖。

### 4.4 预取下一页（上滚丝滑，2026-09）

- `readSessionDisplayTurnPage` 读页返回后，后台用私有 `readTurnPageCore` 读取**下一页**并存入 `prefetchCache`（键 = `sessionPath|indexVersion|before|turnCount`，LRU 上限 `PREFETCH_CACHE_LIMIT = 2` 页）。
- 预取调用 `readTurnPageCore` 而非公共分页方法——**预取不再触发预取**，无连锁递归读盘；失败静默（仅优化，非功能）。
- 命中缓存时直接返回（LRU 刷新）；pi 追加消息/外部重写使 `indexVersion` 变化 → 键失效自动重建。
- 连续上滚体验：请求第 N 页时第 N+1 页已在后台备好，命中缓存零文件 IO（消息内容；索引 stat 仍触达）。

## 5. 渲染层内存预算

### 5.1 会话消息缓存 LRU

- `SESSION_MESSAGE_CACHE_LIMIT = 8`（2026-11 曾收为 6，2026-12 因会话切换闪屏修复放宽回 8：4 分屏常驻 + 3 预览 + 1 切换缓冲）。
- 只淘汰**渲染层**缓存；会话目录与主进程运行期缓存不受影响。被淘汰会话切回时走激活分页（尾部 9 轮）重新拉取。

### 5.2 DOM 窗口：贴底只挂尾部 3 个 agent-run

- `TIMELINE_MOUNTED_TURN_LIMIT = 3`（`turnRenderWindow.ts`）：跟随底部时只挂载最近 3 个 `agent-run`（含工具/思考分组），上滚扩大挂载，回底再卸载旧 `TurnRow`。
- **历史轮折叠即卸载（2026-09 主流实践）**：`TurnRow` 执行过程（思考/工具/中间回答）按轮状态分场景挂载——
  - 非流式轮（`agentRunning=false`，历史已结束轮）折叠时**完全卸载**内容：历史默认折叠，滚动经过几十轮只携带折叠头 + 最终回答；单轮 500 条工具调用时省下海量 DOM。
  - live 流式轮（`agentRunning=true`）折叠时保持挂载（`display:none`）：卸载会重置打字机动画状态。
  - 代价：历史轮 Radix 高度渐变动画退化为瞬时展开/收起（折叠反馈由 toggle 按钮过渡承担，DOM 解脱优先）。
- 最新轮结束 1.5s 且用户无操作时自动收起执行过程（`TURN_SETTLE_IDLE_COLLAPSE_MS`），再把本轮起始消息放到视口中上方；用户任何输入/滚动/移动都会取消，回底弹簧不受影响。

### 5.3 临时历史释放：回底稳定 1.5s

- 上翻补历史 → `prependSessionHistoryPageAtom` 把页 prepend 到 runtime atom 的 `history` 前缀（按 `messageEntryKey` 与窗口段接缝去重，`indexVersion` 变化整段失效）。
- 回底且 `autoScroll` 稳定 **1500ms** 后 `clearSessionHistoryAtom` 清空前缀，atom 回到「最近 9 轮窗口段」；再次上翻走「atom → 主进程缓存 → 文件」重新拉取。
- 防竞态：清理成功即推进 load 序号并复位 loading——在途页响应被 `latestLoadBySession` 丢弃；atom 层拒绝「history 已清空后的续页」（`before !== undefined` 且无 history → false）。

### 5.4 滚动自动加载与程序化滚动抑制

- disk（无 agent 纯浏览）与 runtime（有 agent）**两条读取路径共享同一轮次协议（2026-09 统一）**：
  - **首开**：disk 路径 `readRecordMessagePage(sessionId, undefined, DISK_INITIAL_TURN_PAGE_SIZE = 9)`；
  - **翻页**：disk 与 runtime 均为 `RUNTIME_HISTORY_TURN_PAGE_SIZE = 3` 轮/页（`useSessionTimelineController.ts`，2026-09 删除「按消息条数 100」旧页大小）。
  - 游标：disk 用数值 `nextBefore` + `nextBeforeEntryId`；runtime 额外走主进程缓存命中（`tryReadRuntimeTurnPage`）。
- 上滚到顶部 `HISTORY_AUTO_LOAD_THRESHOLD = 8px` 内才触发按轮补历史（3 轮/页），滚一次加载一页；进入顶部阈值区（视口 40%，下限 120px）先扩 DOM 窗口消费 atom 已加载轮次（本地无 IPC，触顶也先扩本地 cohort），窗口挂满后才翻 IPC 页。
- 监听器在 controller（单一 owner）；`programmaticScrollRef` 抑制程序化滚动（prepend 补偿 / turn 窗口展开补偿 / 贴底 / 跳转）派生的 scroll 事件，防止补偿后 scrollTop ≤ 8px 连锁翻页；rAF 兜底清标记（无位移时不产生事件）。
- 跟底中跳过 prepend 锚点恢复（贴底引擎负责生长补偿），避免把用户拽回旧位置。
- 跳转导航（刻度/消息定位）期间解除轮数窗口（`jumpNavigationActive`），目标行不在窗口外被裁；回底/切会话恢复。

## 6. 身份对齐（entryId 与数值游标）

两个下标空间：**运行时数组**（renderer/main 内存）与**文件消息空间**（activeMessageEntries 下标）。跨空间唯一稳定锚点是 pi 的 entryId。

- **投影**：`AgentMessageProjector` 按 user/assistant/toolResult 消费 `activeEntryIds` 槽位（compactionSummary/branchSummary/非角色条目不消费），生成 `meta.entryId`。
- **trim 同步裁剪**：`loadMessages` 先 `trimHistoryMessages`，随后按 `countRoleMessagesBefore` 同步切片 `activeEntryIds`——保留消息拿到真实 entryId，编辑/删除/重发不会落到会话最早的条目（曾复现 q4→u1 错配）。
- **缓存优先分页**：`tryReadRuntimeTurnPage` 以 `beforeEntryId` 为锚在运行期缓存切片；数值 `before` 先经 `resolveEntryIdAtPosition` 换算成 entryId 再查缓存，`pos === 0`（锚点是缓存最旧条目）回退文件。
- **无 entryId 的窗口**（大历史 skipEntries）：渲染层以 `windowStartFilePos`（§3.3）为数值游标发首次补历史请求，主进程缓存/文件路径都能消费。
- **IPC 映射**：`sessionIpc` 经 `SessionRuntimeCoordinator.getTarget(sessionId)` 把稳定 sessionId 解析为运行时 agentId 再访问 AgentManager 缓存；`tryReadRuntimeTurnPage` 内另有会话路径守卫（防替换/重绑串读）。

## 7. 压缩（compaction）语义

- **JSONL 保留完整历史**：pi 的 compaction 只压缩模型上下文，会话文件里压缩点之前的消息一条不删；索引/分页包含压缩点前全部消息，压缩前历史由翻页像正常对话流一样逐条可见。
- **压缩卡片**：文件路径 `readSessionDisplayMessages` 在 `firstKeptEntryId`（保留起点）之前插入 `compactionSummary` 卡片（归档消息之后、保留消息之前）；runtime 路径由 `AgentManager.loadMessages` 从 `scanCompactions` 补卡片并插到列表最前。
- **卡片去重**：两个转换器共用同一 projector，卡片 id 均为 `${agentId}-meta-N`；翻页前缀与窗口段按 `messageEntryKey` 去重，不会出现两张卡片。
- **卡片视觉**：与思考卡片同构（`CompactionCard`，lucide 图标标签行 + 虚线内容框 + 左下角展开按钮）；点开展示**压缩摘要全文**（产品意图：看摘要，不看归档；`readArchivedMessages` 为已删除的死设计）。
- **裁剪保留**：`trimRuntimeCache` 先取头部系统摘要卡片、裁剪后重新 prepend，运行中 12 轮裁剪不丢卡片。

## 10. 已知限制

- **数值游标为 best-effort**：skipEntries 路径的 `headOffset = 文件活动消息数 − 缓存角色消息数`，文件含非角色 message 条目（system 等）时偏大；entryId 锚点仍是首选，数值游标只作无 entryId 时的兜底。
- **cache 命中页仍依赖索引 stat/读取**：`tryReadRuntimeTurnPage` 计算 `total`/`nextBefore`/`indexVersion` 会触达 `SessionHistoryReader` 索引（冷索引需全量构建一次）；「零文件 IO」仅指不读消息内容。
- **压缩会话分页未游标化**：`hasCompaction` 路径走全量读取 + 切片（50MiB fixture 覆盖），大压缩会话翻页有一次性全量成本。
- **匿名/无文件会话**：无 sessionPath 时无数值游标（`headOffset = -1`），渲染层回退 entryId 锚点；匿名会话无文件可翻，行为不变。
- **预取非持久**：预取页只存主进程内存（LRU 2 页），应用重启/索引失效后重建；预取失败静默降级为常规读页，不影响功能。
