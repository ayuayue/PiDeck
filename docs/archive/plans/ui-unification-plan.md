# UI 统一计划（现状 → 标准 → 分维度收口）

> Status: **Historical（2026-11-02 归档；Wave 0–4 全部完成，冻结标准已进 DESIGN.md）**。现行样式规范见 [ui-and-css.md](../../ui-and-css.md)；本文保留当时的测量数据与渲染态扫描方法。
> 数据采集：2026-10-29，扫描 `src/renderer/src` 1103 个 `.tsx/.ts/.css`。

## 结论先说：网上流传的那套"全站 7 档字号 12–48 / 1120px 栅格"不适用于本项目

PiDeck 是密集的桌面 Operate 界面，不是营销站：

- 界面字号 `11 / 12 / 13 / 14 / 16 / 20` 是**密度决策**，11px 徽章与 13px 控件不可上移到 12/16；
- 字号由 `data-ui-font-size` / `data-chat-font-size` 整体缩放，写死 7 档会绕开这套设置；
- 三栏是**可拖拽像素宽度**（列表 208–440、抽屉 240–880），没有 1120px 内容列；
- "卡片默认无阴影"已经是现状（DESIGN.md 的 Flat Timeline Rule），不是待办。

所以下面三组数字是**从现状提炼并收紧**，不是外来模板。

## 冻结标准（写进 DESIGN.md，新增值必须先改这里）

**字号**：11 / 12 / 13 / 14 / 16 / 20，外加 9–10（dense micro，仅徽章/浮层）与 40（boot 兜底屏）。
字重只有 400 / 500 / 600。标题不超过 600。

**间距**：4px 网格为主（4/8/12/16/24/32/48/64），允许 2/6/10/14 作为图标-文字间隙的半档。
除图形几何（GitGraph 的节点间距）与固定宽高外，**禁止 `[3px]` `[5px]` `[7px]` `[9px]` `[15px]` 这类凑数值**。

**圆角**：2 / 4 / 6 / 8 / 10 / 12 / 14（气泡）/ 999。

**层级**：组件内间距 < 组件间间距 < 区块间距；同一类组件（设置行、列表项、卡片）共用一套 padding。

## 渲染态扫描怎么做（下次直接复用）

设置弹窗是**三级页签**：系统设置 → 配置管理 → Pi 配置管理 → 模型/认证/MCP…，
且所有 tabpanel 常驻挂载。因此：

1. 必须用真实鼠标事件点页签（`locator.getByRole("tab", { name, exact: true }).click()`），
   DOM `.click()` 不触发 Radix 的选中；
2. `exact: true` 必须开，否则「设置」会命中「常用设置」；
3. 扫描前注入 `[role="tabpanel"][data-state="inactive"]{display:none}`，
   否则 `detect --cdp` 会读到隐藏面板，产出假阳性；
4. 每次点完校验可见面板的 `checked` 数量变化，数量不变就说明没切过去。

启动方式：`PIDECK_E2E=1 PIDECK_E2E_USER_DATA_DIR=<临时目录> npx electron . --remote-debugging-port=9222`
（窗口自动摆到屏幕外、不进任务栏，不打扰前台）。

## 纪律

- 一个 wave 一个 commit，出问题可精确回滚。
- 不做"顺手美化"：wave 只处理它负责的维度。
- 视觉改动必须有可验证的判据（值落在刻度上、detect 无 finding、测试全绿），不写"更精致"。
- 并行任务未提交期间不做全局样式改动（冲突面太大）。
