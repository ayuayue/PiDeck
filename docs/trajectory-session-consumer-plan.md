## 0. 目标与完成条件

**复用同一份索引；消息正文继续分页；事实读取有预算且明确覆盖范围；DOM 数量随显示窗口而非会话长度增长。**

完成 S1–S4 必须同时满足：

1. token 刷新不直接触发事实与 model-trace 历史拉取；隐藏轨迹面板后不继续轮询。
2. pi 事实与聊天使用一致的活动分支、fork 来源和版本判断；DSH 只陈述 host 实际提供的范围。
3. 文件未变化时重复读取事实不再读取正文；普通消息尾部追加且事实未变化时复用事实结果。版本检查允许 `stat`，不承诺“零文件系统调用”。
4. 提示词重放、事件保留、IPC 载荷各有独立上界；超限可识别，不把缺失内容伪装成空提示词或完整历史。
5. 账本和概览同时限制挂载数量；翻历史、同 ID 消息更新、工具完成、迟到事实均显示正确。
6. 导轨覆盖预算内的活动用户检查点；已加载项直接定位，未加载项经确认后沿已有边界受控补页，不自动连读或拼接不连续旧页。

## 2. 数据语义与模块边界

### 2.1 对话、事实、覆盖范围分开

- **对话**继续来自本会话消息缓存及已加载历史；不为了轨迹加载全量消息。模型只能声称覆盖这些已加载对话。
- **pi 事实**是当前活动父链上的持久化条目，另带会话头；包含系统提示词、模型/思考档位变化、压缩、自定义、usage、import。不把所有文件条目按文件序混成一个提示词状态。
- **DSH 事实**是 host 提供的事件窗口及运行时连续补帧。窗口未覆盖开头时，首个可见提示词标为窗口快照，不能标为会话 initial。
- 初始提示词/会话头作为会话级信息；普通事实以稳定 entry/seq 锚点归入已加载轮次。pi 读取侧可从索引给出所属用户检查点 `anchorEntryId`，渲染层用消息 `meta.entryId` 对齐。锚点尚未加载或无法确定的事实显示在受预算约束的“窗口外/无法定位”分组，不强塞到第一条已加载用户消息。
- `context_edit` 的排除/替换用于对话与大纲展示；历史提示词快照仍描述当时发生的装载，不因后来编辑用户文本而改写。
- 没有系统提示词事实就显示缺失；不回退到 `pi-system` 模板、UI 缓存推断或 model-trace 请求体。

### 2.2 活动分支与 fork

1. 单文件：会话头加活动父链，沿父链正序重放系统补丁与压缩快照。旁支既不影响装载，也不进入当前分支普通账本。
2. 完整 fork：沿用现有共享 entry ID 判据，子文件包含的前缀为权威，不再拼入父文件后续历史。
3. 增量 fork：复用既有来源解析与链深度/循环保护，但读取事实所需的祖先活动条目，包括 `compaction.systemMessage`。当前 `mergeForkChain` 只继承 `activeMessageEntries`，必须在事实专用只读视图中补足，不能直接把它当作事实全集。
4. 读取偏移始终绑定 `chainHostPath`；缓存版本包含宿主、所有实际使用的祖先版本及分支身份。祖先缺失/链不完整返回 partial，不编造完整初始装载。
5. 普通消息分页行为保持不变。若发现现有链解析不能确定继承边界，事实输出明确降级，不能靠猜测父会话尾部补齐。

## 3. S1：统一有界事实读取、保留与降级

### 3.1 读取流程

1. IPC 只接受合法 session 身份；路径由 catalog/既有 host-path 转换获得，不接受 renderer 提供 offset 或任意文件路径。
2. 从 `SessionHistoryReader` 获取 §2 的事实只读视图。**预算表里的正文读取量不包含既有索引的冷构建**；探针分别计量两者，不能宣称索引回退时也免全扫。
3. 在轻量索引上选择候选，提示词重放优先使用读取预算，普通事件再从近期填充剩余预算，最终按链序输出。系统补丁按活动链正序重放；可从经验证的独立完整快照恢复当前装载，初始摘要另行保留。重放经过的条目数与最后返回的事件数分开计数。
4. 检查 `byteLength`、累计字节与候选数后，小批读取并立即消费释放，禁止建立全部候选行的 `string[]`。单行超限不分配该行大小的 Buffer；被拒绝的候选仍计入 512 个候选检查上限，防止畸形输入靠反复跳过扩大工作量。
5. 某条系统补丁未能完整读取时，后续装载标为不可完整还原；只有字段齐全、能独立建立装载的快照才能恢复已知状态。不能跳过补丁后继续输出貌似完整的全文，也不跨未知区间计算虚假 diff。
6. 普通事件优先保留近期；初始提示词保留摘要位置，提示词全文只保初始与最近 3 次。总事件超限淘汰较早非固定项，但继续在读取预算内重放后续系统条目，避免“达到 240 条就永远看不到后续提示词”。
7. 原始文件/祖先在读取期间改版：结果不能挂到旧版本缓存；最多重试一次，仍变化则返回可重试状态，由下一次可见刷新重试，不在主进程循环追写入。

### 3.2 预算（实施初值，验收后只在本节调整）

字节预算均以 UTF-8 或完整 JSON 序列化长度明确计量，**不是 JS 堆占用承诺**。预算在分配/追加前检查；正文长度上限不能替代行读取上限。

| 对象 | 上界 | 超限行为 |
|---|---|---|
| pi 事实单行正文读取 | 1MiB | 跳过正文，记录 partial；系统条目使装载完整性失效 |
| pi 单次事实正文读取 | 合计 8MiB、最多检查 512 个正文候选（含超限/损坏项） | 停止读取并说明覆盖不足，不再全文件扫描补救 |
| 迁移期旧入口 fallback（源文件扫描） | **独立** 8MiB 源文件扫描预算（不与正文读取共用池）；仅当源文件 ≤8MiB 且默认关闭时尝试一次 | 源文件更大时不走旁路，返回 partial/不可用并说明原因 |
| 提示词重放工作状态 | 序列化计量 ≤1MiB；不同时持有多份完整历史装载 | 超限后不继续宣称完整装载；可由后续独立完整快照恢复 |
| 返回事件 | 总计 ≤240 条，固定项计入上限 | 固定会话头/已知 initial，再取近期事件；`coverage` 标明事件保留截断 |
| 普通摘要 / detail | 分别 ≤512 / 12,000 字符，包含 tools/diff 名称等的结果仍受总载荷上限约束 | 截断并标识；在 stringify 前也要限制输入行，不能只裁输出 |
| 单份提示词展示文本 | ≤96,000 UTF-16 码元（JS length）且 ≤256KiB UTF-8，两个上限都按完整 Unicode 码点边界截断 | 标记 truncated，真实完整长度已知时另存；不截断重放状态冒充完整值 |
| 提示词全文保留 | 初始 + 最近 3 次，去重后最多 4 份 | 更早条目仅留摘要/工具名/变更，标记 omitted |
| 一份事实结果 | 完整序列化 ≤2MiB，含所有正文、元数据、coverage | 先裁普通 detail，再淘汰较早非固定事件；必要时省略全文并标明原因 |
| 主进程事实缓存 | ≤8 个源视图且序列化合计 ≤8MiB，双限制、先到即淘汰 | 同一源视图只留最新版本；同版本请求合并，不保留旧正文副本 |
| 渲染层事实与模型 | 当前挂载轨迹实例各一份投影 | 卸载即释放；不新增跨会话模型缓存 |

`prompt.text` 不再同时复制到事件 `detail` 或模型 `text/detail`；检查器从唯一 prompt 字段取正文。共享 prompt 契约明确区分 `available / truncated / omitted / unavailable`；`text` 缺省表示未保留/不可得，`text: ""` 仍表示已知的显式空提示词。工具名保留现有最多 200 个的口径，并受总载荷限制。

512 个候选是保护阈值，不代表最新提示词必然能在阈值内还原。**候选计的是“正文读取候选”，包含提示词重放链经过的每个系统条目**，不是“返回事件数”：一条需要 601 个补丁才能还原的装载会在第 513 个候选处截断为 partial，不能把“返回事件 ≤240”误读成“只需读 240 行”。已验证 601 条小补丁合计约 33KB 也可能全部参与当前装载；允许从最近可信的完整快照重放，但不能随意只取最后几条补丁。预算耗尽后保留已知摘要并标明完整性，不把截断前的提示词称为最新完整提示。

96,000 个汉字占 288,000 字节，256KiB 为 262,144 字节，因此字节约束可以独立触发；回归测试同时验证字节截断和字符截断均不会切断 emoji 的代理对。

“初始 + 最近 3 次”只对已成功覆盖、重放到的事实成立；预算耗尽、缺祖先或 DSH 尾页不完整时必须显示 partial，不能把窗口内最近三份称为全会话最近三份。超过事件保留上限也不再承诺列出全部变更点。

### 3.3 缓存与失效

- 缓存槽以规范化宿主路径标识当前源视图；校验指纹包含宿主 `(size, mtimeMs)`、实际祖先路径/版本和活动父链选择结果。同一槽位只保存最新有效版本，不把每个文件版本建成一个新槽。保留既有同 size/mtime 改写无法识别的限制，不为此增加内容全量哈希。
- 文件不变：允许版本 `stat`，正文读取为 0。普通消息只追加、旧末尾换行完整且活动事实候选未变时，复用上份事实，不重读旧事实行。
- 上述复用必须建立在索引确认的 append 上；重写、截短、残行补齐、分支或祖先变化均重新选择候选。不能只比较事实条目 ID 或仅看宿主版本。
- S1 不维护跨版本的长期提示词重放器：事实真正变化时在预算内重放。只有探针证明这仍是瓶颈，才考虑后续增量化。
- 对外 `version` 表示规范化事实内容与 coverage 的版本，普通消息追加但事实不变时保持不变；源文件版本只用于主进程校验。相同输出版本不替换渲染引用。
- LRU/在途表归事实读取器一个 owner，具有 dispose/clear 路径；同时执行的事实物化任务最多 2 个，同版本先合并，超额返回可重试状态而非建立无界队列。失败不缓存成“完整空数组”，不以同路径旧分支结果冒充新结果。

### 3.4 IPC 与 DSH 的明确变更

本阶段**有消费契约变化**：现有 `sessions:catalog-read-process-events` 返回由 `src/shared/types/trajectory.ts` 定义的事实结果，至少包含 `events`、内容 `version`、`coverage` 和结构化不可用原因。区分“完整但无事实”“保留/读取不完整”“读取失败/后端不支持”。不另开第二条同义 facts 通道，不改消息页契约或持久化格式。

`coverage` 必须分别表达来源是否从会话开头覆盖、活动链是否完整、预算内读取是否完成、返回事件是否被裁剪，并给出有限枚举原因。单份 prompt 另标识装载能否完整还原及文本保留状态；事件被淘汰不等于提示词失真，提示词不可还原也不能伪装成“已知全文但展示截断”。工具目录超限同样标记，不把前 200 个名称声称为完整目录。

同步点：`sessionIpc.ts`、`src/preload/index.ts`、`useSessionTrajectorySource.ts`、`src/renderer/src/previewApi.ts`、`src/renderer/src/browserApi.ts`、受影响的测试/类型转发；通道常量仍在 `shared/ipc.ts`。同时调整 `promptSnapshotSummary`、`buildTrajectory` 与检查器对必填 `prompt.text` 的假设，使 omitted/unavailable 不被当作空串。Web 当前无该事实来源，继续明确返回不支持，不趁机扩建 Web 轨迹 API。实现前按项目契约变更流程确认这组具体改动。

DSH 必须一起完成：

- `DshAgentManager` 将 `hasMore`/连续重放情况传给 collector；覆盖历史冷读、attach、restart/恢复、fork、backfill 与 mux 补帧入口，不能只改纯函数。
- 在有限 host 页上工作，不为证明 initial 循环读取整段历史。未知起点使用窗口快照语义；未知前态不生成“相对会话初始”的虚假 diff。
- 当前装载独立于经过淘汰/省略全文的事件数组，不能继续从 `prev` 的展示文本反推工作状态；幂等与 seq 去重保持有效。
- 共享事件/输出预算；host 传输与页大小仍沿用既有能力，不声称本阶段已限制 host 原始响应的全部内存。

### 3.5 降级与验收

- sidecar 关闭、缺失、超时、表损坏：由既有 `SessionHistoryReader` 回退 TS 索引，同一事实算法继续执行。
- S1 迁移期保留旧读取入口，但先使它复用相同的活动链选择、提示词重放与保留策略。只在索引不可用且旧路径确实能恢复时尝试一次；sidecar 失败应先走上面的 TS 索引回退，不直接转旧扫描。
- fallback 源文件扫描按 §3.2 单独一行计量：**独立 8MiB 预算，不与“事实正文读取 8MiB”共用池**；源文件超过 8MiB 时不做旁路重扫，直接返回 partial/不可用并说明“索引不可用且会话过大”。因此旧入口的“独立恢复能力”只对 ≤8MiB 源文件成立；验收用例要按这个边界写，不能拿大会话声称已恢复。仍受单行、候选、输出预算和版本检查约束；索引量级的量不因限额变大而放宽。未完整确定活动链时不得输出推测装载。文件不存在、权限错误、超预算或单纯版本竞争均不触发旁路重扫。
- parity 全绿是新路径启用门禁。自动 fallback 必须先有“索引结构/投影不可用、源文件仍可读、旧路径确实可恢复”的故障用例；没有这种证据，就仅保留旧入口用于对照与整组回滚，不接自动旁路。切换交付时不同时删除旧入口。
- 移除生产 fallback 的条件：相关后端/分支/fork 正常语义与预算用例全绿，索引故障注入均已由 TS 索引回退或明确不可用覆盖，直接调用者已迁移，并保留整组回滚点。不存在可恢复的独有故障后移除自动路径；禁止长期维护第二套分支算法。
- 正常同分支小样本与既有输出语义对照；旁支、完整/增量 fork、祖先变更/缺失、context_edit、截短、同长度改写（mtime 变化）、末尾残行分别测试。TS 与 sidecar 输出必须一致；B1/B2 等已知错误按修正语义验收，不以复刻旧错误为 parity。旧入口若继续服务生产，也必须先通过相同正确性与预算用例。
- 240 条普通事件之后新增 7 次系统提示变化，预算内仍能看到最近提示及初始摘要；超过 240 次提示变化时不突破事件预算且明确截断。
- 中文/emoji 的 4 份最大快照、巨型 custom 行、累积 sections 膨胀、损坏系统补丁均验证预算与完整性标记；缺失文本不能显示为“0 字符的完整提示”。
- 用假文件系统/计数器验证：热命中正文读取 0；普通消息尾增量不回读旧事实；并发同版本只物化一次；超限行未分配全文 Buffer；普通刷新失败不触发全扫；仅约定的索引不可用能触发一次有界 fallback。
- DSH 尾页不完整不出现 initial；回放去重、工具增删、压缩恢复与共享上限同时过测。

## 4. S2：事件驱动刷新与时钟治理

本阶段消费 S1 的事实版本，不再改事实读取协议。先移除 token 级触发，再用少量局部状态做去重与作用域隔离，不建立通用调度框架。

### 实现

1. 将事实和 model-trace 拉取从 `cachedEntry.revision/updatedAt`、`messages.length` 的高频变化中解耦。首次打开、session/runtime 代次或路径变化、回合开始/结束、压缩状态变化、模型/思考档位变化、历史 mutation 完成及用户显式刷新负责触发；只订阅相关字段，不依赖整个 runtime 对象。
2. 复用 `isSessionTurnRunning(state, status)` 与 `state.isCompacting` 判断活动。仅轨迹面板可见且会话活动时，每 5 秒最多一次兜底刷新；静态历史、隐藏和卸载均不轮询。兜底用于补同一回合内无独立通知的事实，不代替回合结束刷新。
3. 每类数据最多一个进行中请求；期间重复触发只留一个待刷新标记，完成后检查作用域再决定是否续读。主进程同源版本合并仍由 S1 负责；热命中不能作为删除冷读去重的理由。
4. 作用域绑定 `sessionId + agentId + runtimeGeneration + sessionPath`；历史结果核对 session/path 与请求序号。隐藏/切会话清 timer 并递增序号，立即作废迟到响应，不能等下一次请求才作废。
5. 历史编辑/删除/重发完成复用 mutation 生命周期；单纯 prepend 历史页不重读全会话事实。外部离线改写在重新打开或显式刷新时校验，不新增文件 watcher。
6. model-trace 保留既有接口与归属校验，同样去掉高频触发；没有可归属 agentId 时不扫描全部日志再返回空结果。事实缓存不等于 trace 历史缓存，本阶段不改追踪存储协议。
7. `buildTrajectory` 的输入只包括消息与 extras，静态 domain 与活动时钟分离。可见组件用低频时钟推进活动时长，timer 成对清理，hover/拖动不触发模型折叠。
8. 用 S1 内容版本保持未变化事实的渲染引用稳定；trace 摘要内容相同时也保留引用。不对整份消息做 JSON 序列化比较，不承诺一次缓存命中的端到端成本为 0.1ms。

### 验收

- 假时钟下，200 次消息 flush、持续活动 10 秒且无额外语义事件，事实请求至多“首次 1 次 + 兜底 2 次”，终态额外最多 1 次；同类在途请求始终 ≤1。
- 模型/思考档位或压缩状态变化可触发刷新，不必等待兜底；重复通知合并，不建立无界队列。
- 闲置/隐藏/卸载后没有周期请求；A→B 切换、同 session 重启后的旧结果不能覆盖当前数据。
- 同 ID assistant 完成、工具更新、消息 prepend 正常呈现；相同事实版本不额外重建模型，事实刷新不阻塞消息流。
- 固定数据下 hover/拖动 3 秒，`buildTrajectory` 新调用次数为 0，活动时长继续推进。
- 失败显示可重试状态；已有同作用域数据可保留并标为刷新失败，不清空后冒充完整空历史，不跨作用域复用。

## 5. S3：账本和概览一起限制渲染成本

### 实现

- 按轮分组从 `buildTrajectory` 结果派生本地渲染窗口，初始显示尾部 3 轮；更早/更新按 3 轮 cohort 切换。窗口策略放纯模块，不修改消息缓存与历史游标。
- 单轮采用现有默认 120 步作为轨迹记录挂载上限；查看更早/更新记录时滑动步窗口，不随点击累加挂载。会话级/窗口外事实共享额外 120 条挂载预算，避免每新建一个分组就再增加一份额度；不提供无上限的“全部展开”。
- 概览按 lane 和像素位置聚合：每 lane 最多 `min(250, ceil(width / 4))` 个标记，选中记录最多另加 1 个。保留首尾与活动区间信息，同桶显示数量，点击定位代表记录，完整明细仍在账本。
- 概览点击更早的已加载记录时，将本地渲染窗口切到目标附近 3 轮并定位；提供回最新入口。这里只换 DOM 窗口，不触发 detached 数据分页或读取未加载正文。
- 滚动恢复记录稳定记录 ID、窗口位置与偏移，替代仅靠 `scrollTop` 猜位置；沿用 session 级 Jotai 状态管理，只保存最多 8 个会话的轻量锚点，删会话/消息缓存释放时清理。窗口改变后选中记录检查器保持正确。
- 只复用已有窗口常量/预算，轨迹窗口函数独立可测；不新建虚拟滚动基础设施。UI 使用 Tailwind/shadcn，文案中英同步、简转繁生成，键盘操作不依赖 hover。

### 验收

- 15k 消息样本初次打开、持续流式与单轮数千步，账本挂载记录 ≤`3 × 120 + 120 = 480`，反复翻看也不累加；概览标记 ≤`4 × min(250, ceil(width / 4)) + 1`。
- 鼠标拖动范围、缩放、选中、检查器、键盘操作、查看更早和回最新均可用；范围过滤不偷偷取消挂载预算。
- prepend 历史、工具完成和事实迟到后锚点/选中不串行；切抽屉 tab 后恢复到同一记录附近。
- 使用浏览器 Performance/React Profiler 分别量折叠、commit、布局绘制；不能拿 Node 纯函数时间代表界面改善。

## 6. S4：全量用户检查点导轨与受控导航

### 数据与身份

1. pi 从活动消息索引派生 `{ entryId, messageIndex, turnOrdinal, timestamp }`，过滤 `contextEdits.excludedEntryIds`；标题优先使用有效替换文本。`messageIndex` 是原 `activeMessageEntries` 坐标，不是过滤后序号或 JSONL 行号；`turnOrdinal` 按既有 user/assistant 发言权边界计算，用于估算距离。
2. `readSessionDisplayTurnPage.before` 是排除式上界；目标 `messageIndex + 1` 只保证包含目标自身，可能截掉同轮回答，也不能保证与当前窗口连续。S4 沿已有 `nextBefore`/`beforeEntryId` 从当前窗口向前补页，不能直接读孤立目标页后 prepend。
3. 索引 ID 经 `meta.entryId` 映射到已加载 `ChatMessage.id`。无可靠 entryId 的 live 消息暂作加载段检查点，不靠相同文本/时间戳猜测去重；持久身份到达后再合并。
4. 以用户消息检查点计数；连续 user 可能属于同一对话轮，不把“2,000 个检查点”写成“2,000 轮”。全量指索引覆盖，不要求窄导轨为每条数据绘制一个刻度。

### 接口与预算

- 新增独立 outline 读取与单项标题读取 IPC，名称集中 `shared/ipc.ts`；共享类型、main 校验、preload、preview/browser fallback 与测试一起更新。参数仅含 session、entryId、已知版本，不接收任意路径/offset。
- 每次目录响应最多 10,000 项且完整序列化 ≤2MiB；超限保留首项与最近检查点并返回覆盖信息。主进程不另缓存一份完整大纲，复用已有显示索引。
- 标题按需读：一次最多一个目标行、≤1MiB，解析后取有效正文前 80 字并复用引用/chip 标题口径；**不是直接取原始 JSONL 前 80 字节**。超限只显示时间/序号占位，不加载附件或追读多行。
- 标题缓存最多 128 项/64KiB，键含源版本与 entryId。版本变化拒绝旧标题结果；预算不足允许不缓存。
- renderer 按 session atom 订阅，先显示已有加载段，异步合并索引段；使用 `outlineRevision`/源版本触发，不随 assistant token 刷新。最后一个订阅卸载时释放该 session 的索引投影与在途请求，不把全量大纲留在无限增长的 atom-family 闭包里。
- DSH、ACP、生图或索引不可用时保留当前已加载消息大纲，不额外扫描后端历史。

### 交互与验收

- 已加载项沿用 `jumpToMessage`；未加载项点击显示轻确认与估算距离。N 由 `turnOrdinal` 推算，不把用户检查点数量直接当轮数；悬停/键盘聚焦仍可懒读标题。
- N ≤20 时，经一次确认从已有边界按最多 3 轮一页连续补齐；累计最多 20 轮、最多 7 个前台分页请求，到目标已加载立即停止并定位。剩余预算不足 3 轮时缩小本页轮数；若单页消息条目上限导致预算内仍未到达，停止并明确提示，不继续追读。N >20 或距离不可可靠估算时，确认只允许前进一页，并明确尚未到达目标。
- 这里的页数限制指前台请求与纳入连续窗口的页；既有分页入口会预取下一页，探针须单独计量，不能声称远目标仅一次磁盘读取。保持现有单页预取，不额外叠加导航预取。
- 用户取消、切会话、runtime 换代、索引版本漂移、分页失败或游标无前进时立即停止后续请求，不自动重试或绕过缓存守卫。`beforeEntryId` 失配时不能利用现有入口“回退尾页”的行为续接；结果未通过连续 prepend 校验就停止。已成功加载的连续页保留，孤立目标页与回最新的 detached 数据窗口另归 S5。
- 复用 `planRailTicks` 抽稀，补当前已加载范围高亮；没有锚点映射的项不能被标为当前窗口。
- 2,000 个检查点的预算内样本目录完整，刻度数量仍服从像素预算；悬停首次最多读一行，同版本重复悬停不再读正文。
- 覆盖删除/编辑、分支切换、fork、live→持久 ID、分屏、迟到标题、超长带附件消息与无索引降级；补 N=20/21、未知距离、连发 user、巨轮被页条目上限截断、分页中取消/改版/锚点失配/失败/游标停滞，确认不会越过轮数/请求预算或破坏连续前缀。

## 7. S5：有证据再立项的后续能力

以下不阻塞 S1–S4，也不计入其完成承诺：

| 能力 | 启动条件与必要边界 |

### 8.2 性能探针与退出条件

S1 落地时增加 `scripts/probeTrajectoryRead.mjs`（当前尚不存在），复用测试加载 helper，只读指定真实文件，不输出提示词正文/私有路径。合成 fixture 与探针 sidecar 缓存仅写入探针自有临时目录，结束清理；禁止删除或改写用户缓存来制造冷启动条件。每个场景超时 10 秒，失败即记录并停下，不换路径重复试探。

分别输出：索引构建/加载、`stat` 次数、事实正文 read 次数/字节、候选与保留数量、重放/模型折叠耗时、结果序列化字节、是否 partial。冷无表、磁盘表命中、内存热命中、普通消息追加、事实追加分别统计，不能混成“首次 <20ms”。

- 正确性与预算是硬门禁；耗时报告同机同样本的中位数/p95、样本数与预热条件。
- 热命中正文读取 0、普通追加不回读旧事实、隐藏面板请求 0、默认 DOM 有界是可重复的主要收益判据。
- 不为得到某个数字跳过分支/版本/完整性检查。若优化只增加维护成本且实测无收益，停在上一阶段，不继续增量化。
