# PiDeck 开发规范

> 基于 Electron 38 + React 19 + TypeScript + Vite 的 AI 编码助手桌面工作台。
> 本文档面向 AI 助手和人类开发者，约定本项目必须遵守的规则、模式与边界条件。

---

## 一、项目总览与架构原则

### 1.1 项目定位

PiDeck = 桌面工作台，用于管理多个 pi AI 编码助手（Agent）的本地会话。它不是 pi 本身，而是 pi 的桌面 UI + 进程管理器。

**核心边界：**
- pi 负责 Agent 行为、工具调用、会话读写、模型调用、上下文管理 —— **pi 的事不要替它做**
- PiDeck 负责窗口管理、多项目工作区、进程生命周期、会话文件浏览/导入、Git 面板、终端、设置 —— **UI 框架的事 pi 也不要做**
- 两者通过 RPC（stdio JSON-RPC）通信，PiDeck 启动 pi 子进程后通过 stdin/stdout 收发消息

### 1.2 关键架构决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 进程模型 | 主进程 + 沙箱渲染进程 + 工具进程 | Chromium 多进程架构，安全隔离 |
| IPC 通信 | `contextBridge` → `invoke`/`handle` | 不暴露 `ipcRenderer` 全局，按通道限制权限 |
| 建模文件 | `.mjs` 测试 | ESM 原生支持，无 babel 依赖 |
| 样式方案 | Tailwind 4 + CSS 语义 token | 保证暗色/亮色模式一致性 |
| 状态管理 | zustand | 轻量、无 Provider 树、类型安全 |
| 构建 | electron-vite + electron-builder | 快速 dev server + 完善的打包分发 |
| 多入口 | index.html（主窗）+ pet.html（宠物悬浮窗） | 宠物独立窗口免干扰主布局 |

## 三、TypeScript 编码规范

### 3.1 严格模式

tsconfig.json 已启用 `strict: true`，新增代码必须遵守：

```typescript
// ✅ 必须显式标注函数返回值类型（推断不清晰时）
function validateSender(frame: WebFrameMain): boolean {
  return new URL(frame.url).host === 'trusted-app.com'
}

// ✅ 使用 type 而非 interface（项目惯例，interface 仅用于声明合并场景）
export type Project = {
  id: string
  name: string
  path: string
  lastOpenedAt: number
  kind?: 'chat'
  environment?: 'windows' | 'wsl'
}

// ✅ readonly 标记不应修改的属性
export type AppSettings = {
  readonly windowBounds?: { x: number; y: number; width: number; height: number }
  theme: 'light' | 'dark' | 'system'
}

// ✅ 使用 const assertions 定义常量
export const IPC = {
  PROJECTS_LIST: 'projects:list',
  PROJECTS_ADD: 'projects:add',
} as const
```

### 3.2 noUnusedLocals / noUnusedParameters

当前为 `false`，但新增代码**不应该**有未使用的导入和参数：

```typescript
// ❌ 未使用的导入
import { existsSync } from 'node:fs'
// ✅ 移掉或用 `type` 标记
import type { AppSettings } from './types'

// ❌ 未使用的参数
function handler(event: IpcMainEvent, title: string) {
  console.log(title)
}
// ✅ 用下划线前缀标记有意不用的参数
function handler(_event: IpcMainEvent, title: string) {
  console.log(title)
}
```

### 3.3 IPC 通道名常量

所有 IPC 通道名必须集中在 `src/shared/ipc.ts` 的 `ipcChannels` 对象中，不允许在业务代码中硬编码字符串：

```typescript
// ❌ 禁止
ipcMain.handle('my-custom-channel', handler)

// ✅ 必须
import { ipcChannels } from '../shared/ipc'
ipcMain.handle(ipcChannels.myCustomChannel, handler)
```

### 3.4 类型共享

主进程和渲染进程共用的类型放在 `src/shared/types.ts`，不要复制定义：

```typescript
// ✅ preload 和 main 用同一套类型
import type { AppSettings, SessionSummary, AgentTab } from '../shared/types'

// ✅ invoke 调用链类型安全
const result = await ipcRenderer.invoke(ipcChannels.settingsGet) as Promise<AppSettings>
```

## 四、Electron 主进程规范

### 4.1 窗口创建

```typescript
// main/index.ts
const mainWindow = new BrowserWindow({
  show: false, // 先隐藏，ready-to-show 后再显示，避免白屏
  webPreferences: {
    contextIsolation: true,    // 必须：上下文隔离
    nodeIntegration: false,    // 必须：禁用 Node 集成
    sandbox: true,             // 推荐：沙箱模式
    preload: preloadPath,      // preload 脚本
  }
})

mainWindow.once('ready-to-show', () => {
  mainWindow.show()
})
```

### 4.2 IPC 注册模式

```typescript
// 单向（send/on）
ipcMain.on(ipcChannels.setTitle, (_event: IpcMainEvent, title: string) => {
  const win = BrowserWindow.fromWebContents(_event.sender)
  win?.setTitle(title)
})

// 双向（invoke/handle） — 优先使用
ipcMain.handle(ipcChannels.settingsGet, async (): Promise<AppSettings> => {
  return settingsStore.getAll()
})

// 主进程→渲染进程（webContents.send）
mainWindow.webContents.send(ipcChannels.agentsState, tabs)
```

### 4.3 安全校验

```typescript
// validateSender — 每个 IPC handler 都应使用
ipcMain.handle(ipcChannels.getSecrets, (e) => {
  if (!validateSender(e.senderFrame)) return null
  return getSecrets()
})

function validateSender(frame: WebFrameMain): boolean {
  if (!frame) return false
  const host = new URL(frame.url).host
  return ['app://localhost', 'localhost:5181'].includes(host)
}
```

### 4.4 生命周期

```typescript
app.whenReady().then(() => {
  createWindow()
  app.on('activate', () => {
    if (BrowserWindow.getAllWindows().length === 0) createWindow()
  })
})

app.on('window-all-closed', () => {
  if (process.platform !== 'darwin') app.quit()
})
```

### 4.5 进程错误处理

```typescript
// 绝不 process.exit — 失败可诊断，不崩溃
process.on('uncaughtException', (error) => {
  appLogger?.error('process', 'Uncaught exception', {
    message: error.message,
    stack: error.stack,
  })
  console.error('Uncaught exception:', error)
})

// Windows 上 EPIPE 管道路径错误要静默处理
process.stdout.on('error', (err) => {
  if (err.code === 'EPIPE') return
  throw err
})
```

## 五、Preload 脚本规范

### 5.1 单一入口

preload 目录仅一个 `index.ts` 文件。所有需要暴露的 API 集中在此文件中，通过 `contextBridge.exposeInMainWorld` 暴露为 `window.piDesktop`。

### 5.2 安全暴露规则

```typescript
// ✅ 正确：按方法维度暴露，不要暴露 ipcRenderer 本身
contextBridge.exposeInMainWorld('piDesktop', {
  projects: {
    list: () => ipcRenderer.invoke(ipcChannels.projectsList) as Promise<Project[]>,
    add: () => ipcRenderer.invoke(ipcChannels.projectsAdd) as Promise<Project | null>,
  }
})

// ❌ 错误：暴露整个 ipcRenderer
contextBridge.exposeInMainWorld('piDesktop', {
  ipc: ipcRenderer  // 渲染进程可以发送任意 IPC
})

// ❌ 错误：直接传递 callback 给 ipcRenderer.on
contextBridge.exposeInMainWorld('piDesktop', {
  onX: (cb) => ipcRenderer.on('x', cb)  // 泄漏 IpcRendererEvent.sender
})

// ✅ 正确：用中间函数包装
contextBridge.exposeInMainWorld('piDesktop', {
  onUpdateCounter: (callback: (value: number) => void) => {
    ipcRenderer.on('update-counter', (_event, value) => callback(value))
  }
})
```

### 5.3 subscribe 辅助函数

```typescript
// preload 中定义的统一取消订阅模式
function subscribe<T>(channel: string, callback: (payload: T) => void) {
  const listener = (_event: Electron.IpcRendererEvent, payload: T) => callback(payload)
  ipcRenderer.on(channel, listener)
  return () => { ipcRenderer.removeListener(channel, listener) }
}
```

## 六、渲染进程规范

### 6.1 共享 UI 组件（必须遵守）

| 组件 | 路径 | 何时用 |
|------|------|--------|
| `Button` | `ui/Button.tsx` | 任何可点击操作按钮 |
| `IconButton` | `ui/IconButton.tsx` | 纯图标按钮（带 `aria-label`） |
| `CloseIconButton` | `ui/IconButton.tsx` | 弹框关闭按钮 |
| `SelectField` | `ui/SelectField.tsx` | **替代所有原生 `<select>`** |
| `TextField` | `ui/TextField.tsx` | 替代原生 `<input>` |
| `Modal` | `ui/Modal.tsx` | 替代手写 `div + onClick` 弹框 |
| `LazyMonacoEditor` | `ui/LazyMonacoEditor.tsx` | 代码编辑器 |

**禁止行为：**
- ❌ 不可以写 `<select><option>` — 用 `SelectField`
- ❌ 不可以写 `<input type="text">` — 用 `TextField`
- ❌ 不可以手写 `div + onClick` 弹框 — 用 `Modal`
- ❌ 不可以自己实现 ✕ 关闭按钮 — 用 `CloseIconButton`
- ❌ 不可以手写 `<button className="xxx">` — 用 `Button`

### 6.2 图标系统

- 图标统一使用 `lucide-react`，**禁止引入其他图标库**
- **禁止用 emoji 作为功能图标**（🚀🔥✅ 只能用于文案/通知）
- 交互图标必须带 `aria-hidden="true"`，可点击的用 `IconButton` + `aria-label`
- 品牌 Logo 必须使用 `LogoMark` 组件（`AppParts.tsx`），不可用 lucide 图标替代

### 6.3 样式规范

- **全局语义 token 在 `styles.css` 的 `:root` 中**，不要写死颜色值
- 使用 Tailwind 4 的 `@theme` 引用语义 token：`bg-(--color-bg-app)`、`text-(--color-text-primary)`
- 暗色模式通过语义 token 自动适配，不写 `@media (prefers-color-scheme: dark)` 覆盖
- 圆角优先 `var(--radius-sm)` / `var(--radius-md)` / `var(--radius-lg)`
- 字号优先 `var(--font-size-body)` / `var(--font-size-caption)` 等 token

### 6.4 弹框尺寸规范

```css
/* 全屏弹框统一尺寸 */
width: min(1300px, calc(100vw - 48px));
height: min(850px, calc(100vh - 48px));
border-radius: var(--radius-lg);
box-shadow: var(--shadow-xl);
```

使用 `Modal` 组件自动应用该规范。

### 6.5 多语言文案

**所有用户可见文本必须在 `i18n.ts` 中定义 key：**

```typescript
// i18n.ts
"app.createAgent": "启动 Agent",
"app.confirm": "确认",

// 使用时
const { t } = useTranslation()
<Button>{t("app.confirm")}</Button>
```

- ❌ 禁止在 JSX 中硬编码中文/英文文案
- ❌ 禁止用固定宽度按钮，要为中英文长度差异留空间
- 日志、调试输出、内部标识符可以硬编码

### 6.6 类型声明

```typescript
// src/renderer/src/types.d.ts
import type { PiDesktopApi } from "../../preload";
declare global {
  interface Window {
    piDesktop: PiDesktopApi;
  }
}

// 使用 window.piDesktop.xxx 时获得完整类型提示
const projects = await window.piDesktop.projects.list()
```

## 七、IPC 通信协议规范

### 7.1 通道命名

```
domain:action          # 格式
projects:list          # 列表查询
projects:add           # 新增
projects:remove        # 删除
projects:changed       # 推送变更（主→渲染）
git:workspace-file-diff # 复合操作
```

### 7.2 双向通信（推荐）

```typescript
// renderer
const settings = await window.piDesktop.settings.update({ theme: 'dark' })

// main
ipcMain.handle(ipcChannels.settingsUpdate, async (_event, patch: Partial<AppSettings>) => {
  return settingsStore.update(patch)
})
```

### 7.3 主进程推送

```typescript
// main — 通过 WebContents 发送
mainWindow.webContents.send(ipcChannels.agentsState, currentTabs)

// renderer — 通过 subscribe 监听
const unsubscribe = window.piDesktop.agents.onState((tabs) => {
  setTabs(tabs)
})
// 组件卸载时调用 unsubscribe()
```

### 7.4 对象序列化限制

IPC 通道使用结构化克隆算法，以下类型**不可序列化**：
- DOM 对象（`Element`、`Location`、`DOMMatrix`）
- Node.js C++ 类（`process.env`、`Stream`）
- Electron C++ 类（`WebContents`、`BrowserWindow`、`WebFrame`）

只能在参数中传递 plain object / Array / primitive / Date / Map / Set。

## 八、状态管理规范

### 8.1 使用 zustand

```typescript
// ✅ 正确：创建 zustand store
import { create } from 'zustand'

type AgentStore = {
  tabs: AgentTab[]
  activeId: string | null
  setTabs: (tabs: AgentTab[]) => void
  setActive: (id: string) => void
}

export const useAgentStore = create<AgentStore>((set) => ({
  tabs: [],
  activeId: null,
  setTabs: (tabs) => set({ tabs }),
  setActive: (id) => set({ activeId: id }),
}))
```

### 8.2 状态变更流

```
主进程 IPC 推送 → subscribe handler → zustand set() → React re-render
```

不将 `ipcRenderer.on` 直接放在组件中监听；而是统一在 React 根层或 hook 中订阅，写入 store。

### 8.3 避免

- ❌ 不要在组件中直接 `ipcRenderer.on`（无法清理、多次注册）
- ❌ 不要用 Redux / MobX（zustand 足矣）
- ❌ 不要在 zustand store 中存不可序列化的值（函数、DOM ref）

```bash

feat: add mermaid diagram rendering
```

### 10.3 工作流程

1. 从最新 `main` 创建短修复分支

6. **禁止在工作过程中自动 commit** — 仅当用户明确要求时才执行

- PR 描述需包含：问题原因、修复摘要、验证命令

## 十三、常见踩坑（项目专属）

### 13.1 进程管理

| 坑 | 说明 | 解决 |
|----|------|------|
| pi 子进程未正确清理 | 切换项目/Agent 时旧进程残留 | 确保 `AgentManager.stop()` 发送 SIGTERM 并等待退出 |
| WSL 路径解析错误 | Windows 路径 `C:\` 和 WSL `/mnt/c/` 混用 | 通过 `environment: "windows" \| "wsl"` 标记，用对应路径转换 |
| EPIPE stdout 崩溃 | dev 模式下 stdout 管道断开 | `process.stdout.on('error', ...)` 静默处理 EPIPE |

### 13.2 渲染进程

| 坑 | 说明 | 解决 |
|----|------|------|
| preload 修改后需手动重启 | Vite HMR 不覆盖 preload | 使用 Forge 模板的 dev server 或手动 `Ctrl+R` |
| 剪贴板文件路径 | Electron 32+ 移除 `File.path` | 使用 `webUtils.getPathForFile()` |
| Monaco 编辑器大文件卡顿 | 超大 JSON/日志渲染 | 已使用 `LazyMonacoEditor`，按需加载 |
| 窗口控制栏被内容遮挡 | 自定义标题栏坐标错位 | 全屏弹框的内容区顶部保留 `padding-top` |

### 13.3 打包发布

| 坑 | 说明 | 解决 |
|----|------|------|
| pnpm 打包找不到依赖 | node_modules 结构差异 | 设置 `.npmrc` `node-linker=hoisted` |
| asar 中 .wasm 无法加载 | sql.js wasm 被打包到 asar | `asarUnpack` 中配置 `sql.js/dist/*.wasm` |
| Windows 代码签名 | 安装包被杀毒软件拦截 | 配置 electron-builder 的 certificateFile |
| 版本号不一致 | package.json 和 lock 不同步 | 发版时核对两个文件的 version 字段 |

### 13.4 源文件同步

| 场景 | 处理方式 |
|------|----------|
| px转rem | `styles.css` 中已有的 `--font-size-*` 和 `--space-*` 变量不可轻易更换单位，只能新增变量 |
| 添加新的 provider 类型 | 在 `src/main/config/` 对应模块添加；同步在 `renderer/src/config/` 添加 UI Tab |

## 十五、AI 助手工作原则

1. **不要替 pi 做事** — Agent 行为、模型调用、会话读写是 pi 的职责，PiDeck 只负责 UI 和进程管理
2. **不要擅自 commit/push** — 只有用户明确要求时才执行，完成后询问用户是否需要提交
3. **不要放过未处理的错误** — `try/catch` 中失败的 IPC 操作需要给用户反馈（toast / error 状态）
4. **不要破坏暗色模式** — 新增 UI 必须用语义 token 适配 light/dark，不可写死浅色背景
5. **不要做大重构** — Issue 修复聚焦单一问题，功能新增保持现有三栏布局和交互风格
6. **先类型后实现** — 先定义类型和 IPC 通道，再实现业务逻辑，最后写 UI
7. **注释写"为什么"不写"是什么"** — 复杂状态流转、边界条件、业务规则需要注释，简单的 getter/setter 不需要
