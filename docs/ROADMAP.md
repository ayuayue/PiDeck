# PiDeck Lite 路线图

目标：在保持「一个 Go 二进制、无 Electron」的前提下，覆盖原 Electron 版 PiDeck 的能力，
并把扩展点做成产品的一部分——插件、主题、命令、键位、后端都可以在不改核心代码的情况下增长。

图例：✅ 已有 · 🟡 部分可用 · ⬜ 未开始 · 🔧 进行中

## 一、架构地基（先做）

| # | 能力 | 状态 | 说明 |
| --- | --- | --- | --- |

| A3 | 插件清单 v2 | ✅ | `runtime: pideck-lite`、显式 schemaVersion 与旧清单内存兼容；六类贡献、启停、错误面板、重新加载、脚手架；三套离线完整示例。自定义 TSX UI/函数宿主仍见 [插件设计](PLUGINS.md) |
| A4 | 主题 v2 | ✅ | 角色色 + 设计 token + 字体 + 圆角 + 终端配色；shadcn/ui 主题文件与 YAML；配色缩略图、导出与删除用户主题 |

| A7 | 事件总线 | ✅ | 9 个事件：turn.start/done、session.created/opened/deleted、theme.changed、plan.finished、git.commit、image.generated；订阅者与插件 hooks（url/command/theme，防递归） |

| A9 | 崩溃与诊断 | ✅ | 进程/日志面板、诊断报告与脱敏诊断包；根级 `core.Catch` 错误边界写崩溃日志并可重载界面，main 兜底记录；启动提示上次崩溃 |
| A10 | 自动更新 | ✅ | EdDSA 签名 appcast、检查更新入口、CI 密钥注入；stable/dev 渠道待拆 |
| A11 | 列表性能 | ✅ | 会话元数据按大小/修改时间缓存并写 `session-meta-cache.json`，热启动只 stat 不读文件；pi 会话库按项目读，没显示的项目只读首行；冷启动并行解析；重命名走配置；设置页只数文件 |
| A12 | 持久化写入 | ✅ | 应用配置复用共享原子写入；每次写入独占同目录临时文件，同一目标的并发保存依次完成，失败清理本次临时文件；沿用调用方的文件权限与现有数据格式 |

## 四、执行顺序

1. **地基**：A1 命令注册表 → A2 键位 → A3 插件 v2 → A4 主题 v2 → A5 设置 schema。
2. **可见能力**：文件编辑器、消息编辑/重发、待办条、修改摘要、会话 fork、内置 Chat。
3. **配置与生态**：模型配置可视化、连接测试、用量统计、Skills/Extensions 管理、提示词库。
4. **系统集成**：托盘、通知、自动更新、日志面板、二维码配对。
5. **后端扩展**：A6 抽象 + ACP（先做通用 ACP，再补预设）→ DSH。
6. **打包与发布**：GitHub Actions 矩阵（Windows/macOS/Linux/Android）、版本注入、Release 产物、自动更新通道。
7. **补缺口**（第三节，按依赖排序）：
   - P0 日常摩擦：消息编辑/删除与真正重试、会话分组、关联会话、ACP 15 预设与安装检测。
   - P1 结构能力：智能体记忆、DSH 后端、ACP 看门狗与按工具记忆、模型目录自动刷新与 OAuth 登录页、拼音检索。
   - P2 生态与分发：商店索引、插件市场官方源、深度链接与 dev/stable 通道、云同步、移动端通知与定位。
   - 单独立项：内置浏览器 Agent / CUA、Office 与媒体预览、远端文件编辑（都依赖新的一层，不和日常补丁混做）。

每一步都要求：`go tool nsgo check`、`go tool nsgo test -- -short -count=1 -timeout=20m` 通过；涉及界面的加无头 UI 测试；格式与行为写进 README 或 `docs/`。
