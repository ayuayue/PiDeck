# PiDeck V2 路线图

目标：在保持「一个 Go 二进制、无 Electron」的前提下，以 NSGo 原生方式对齐原 PiDeck 的核心使用体验，
并把扩展点做成产品的一部分——插件、主题、命令、键位、后端都可以在不改核心代码的情况下增长。

2026-11-27 修复 Git 更改与概览的滚动条遮挡，并排查桌面和客户端的同类滚动容器；稳定内容留白及窄栏回归范围见 [滚动布局排查](scrollbar-layout-audit.md)。

2026-11-27 左侧项目区与设置页按右侧 Tab 的 13 点文字基准统一主字号，设置说明采用 12 点层级，导航切换保持字重稳定；文字层级见 [侧栏与设置](SIDEBAR.md#侧栏与设置的文字层级)。

2026-11-27 运行环境页按 pi、外部编辑器、网络代理、远程运行和数据目录分组；pi 展示状态、版本、路径与错误，支持自定义程序及恢复自动检测；编辑器支持带品牌图标的程序列表、检测、添加、默认切换与删除。移除该页低频的会话链接注册项，保留已有链接功能；配置版本 7 兼容原有默认编辑器，并区分自动发现与显式空列表。

2026-11-27 快捷键设置按用途分组，提供命令与键位搜索、已修改筛选和空结果恢复入口；回车或移开焦点保存，冲突就地显示占用命令，单项恢复与全部恢复默认均有明确状态，全部恢复前需确认。Windows 原生回归覆盖保存落盘、取消绑定、冲突拒绝、筛选保留和窄窗口布局。

### 首版取舍（2026-11-20）

首版按高频使用路径对齐体验，优先采用 NSGo 已有的原生控件与系统集成，不再把逐项复刻作为发布前提。

2026-11-21 会话视觉基线按 Electron 版重新校准：16 pt 正文与 80% 阅读列、系统 CJK 字体回退、纸面/白卡分层、输入框比例和常用/次要回复操作分层。设计依据、验证与保留差异见 [会话设计对齐记录](DESIGN-ALIGNMENT-2026-11-21.md)。

桌面新会话沿用同一输入框和阅读列。首条消息前居中输入，项目建议以 32 点高、无常驻描边的紧凑文字按钮提供可编辑的草稿，按内容宽度排列并自动换行。首条消息出现后输入框回到底部，保留焦点和草稿。

欢迎引导页与新会话页共用纸面背景和阅读列宽，采用紧凑品牌标题、32 点操作按钮与轻量项目列表；保留真实项目、新建、直接对话、导入和文件夹选择流程。

桌面对话按发送方区分：用户身份栏和浅色气泡靠右，AI 身份栏与回复靠左。双方头像默认 32 pt、名称 15 pt 半粗体、时间 12 pt，并跟随聊天字号放大；长 agent 名称省略且保留时间，AI 的 Markdown 与工具过程保持完整阅读宽度。

执行过程中的图片与文件入口独立于工具正文折叠显示：返回的图片可直接查看、另存；本机项目内的图片显示缩略图，Markdown、CSV/TSV、PDF、音视频、Office 和代码文件复用现有查看器或编辑器。每个工具最多展示 4 个本地文件，过大或无法解码的图片保留文件入口；项目外路径、越界链接、缺失文件和远程项目不会自动读取本机文件。

2026-11-21 对照 PiDeck dev v0.13.1 的系统设置、配置管理、会话、输入区、弹窗、右侧面板和终端页面，并按 V2 的数据所有权与宿主边界改进现有流程；此 UI 对照记录不代替下方 v0.12.0 功能基线或 v0.13 功能验收。

## 四、执行顺序

1. **地基**：A1 命令注册表 → A2 键位 → A3 插件 v2 → A4 主题 v2 → A5 设置 schema。
2. **可见能力**：文件编辑器、消息编辑/重发、待办条、修改摘要、会话 fork、内置 Chat。
3. **配置与生态**：模型配置可视化、连接测试、用量统计、Skills/Extensions 管理、提示词库。
4. **系统集成**：托盘、通知、自动更新、日志面板、二维码配对。
5. **后端扩展**：A6 抽象 + ACP（先做通用 ACP，再补预设）→ DSH。
6. **打包与发布**：GitHub Actions 矩阵（Windows/macOS/Linux/Android）、版本注入、Release 产物、自动更新通道。
7. **剩余验收与上游边界**：
   - 使用真实账号验收 DSH 模型回合、微信、付费生视频、云同步与 SSH；设备验收原生 WebView、麦克风、媒体与通知权限。
   - 消息原地编辑/删除仍需安全的 writer 停止、重载与落盘一致性实现；聊天正文选区浮钮已接入并有无头与 Windows 原生回归，macOS/Linux 正式验收待完成；桌面 CUA、桌宠嵌入运行时继续等待公开 SDK/运行时能力。
   - 完整记录派生工作流图、离线推送另需实现；macOS 签名/公证需要维护者配置 CI 凭据并发布验收。

每一步都要求：`go tool nsgo check`、`go tool nsgo test -- -short -count=1 -timeout=20m` 通过；涉及界面的加无头 UI 测试；格式与行为写进 README 或 `docs/`。
