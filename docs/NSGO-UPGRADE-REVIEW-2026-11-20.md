## 值得主动接入

### 1. 原生聊天选区翻译：已接入，平台验收继续

- **审查时现状**：`internal/workbench/ui_chat.go` 的 `transcript-column` 已有 `Selectable: true`；`ui_translation.go` 已有原文保护、模型调用和翻译窗口。当时只有整条回复与网页选区入口。
- **SDK 已具备**：[`View.OnTextSelection`](https://github.com/nsgo-dev/nsgo/blob/c70af8a79201695f8b37d76fc4436430d08d6e64/core/element.go) 现在接收 `core.TextSelection`，同时给出所选文字和边界；旧版回调只给边界。这一项已不再受“缺少选中文字接口”阻挡。
- **已实现**：在现有正文选择区域接收选区，显示稳定 TestID 的翻译入口，调用现有 `openTranslationWith`。选择本身不发模型请求；会话切换、滚动、缩放和取消会清理入口，不读取或覆盖剪贴板。
- **收益**：只翻译选中的段落，减少手工复制和整段模型输入；不用另造翻译引擎、配置或 HTTP 契约。
- **验收**：无头 `nsgotest.App.SelectText` 检查选区内容、清除、跨会话和已有翻译保护；Windows 原生覆盖局部文字、跨行选区、浮钮位置、主题与窄窗口。macOS/Linux 仍待正式验收；不增加手机翻译 API。

### 2. 手机实时扫码连接：优先

- **现状**：`internal/client/connect.go` 的 `scanQR` 是 `TakePhoto` 拍一张照片后交给 `goqr`；用户需要完成拍照步骤。
- **SDK 已具备**：[`Scope.ScanCode`](https://github.com/nsgo-dev/nsgo/blob/c70af8a79201695f8b37d76fc4436430d08d6e64/core/scan.go) 在 iOS / Android 展示实时相机，识别后返回文字；`Env.CanScanCode` 判断能力，`nsgotest.App.ScanCode` 可注入测试结果。
- **最小改动**：有能力时使用实时扫码，结果继续经过现有 `newRemoteClient` 与连接流程。取消不报错；无能力、权限拒绝或无相机时提供现有粘贴与相册入口。
- **必需配套**：已在 `nsgo.yaml` 加入 iOS `NSCameraUsageDescription`、Android `CAMERA` 权限和权限文案目录；根目录 catalog 已由应用导入，权限提示可以随系统语言显示。
- **保留内容**：相册识码仍使用 `goqr`；电脑显示二维码仍使用 `go-qrcode`。实时扫描接口没有替代它们，因此本次不删除这两项直接依赖，也不另做识码器迁移。
- **接入结果（2026-11-21）**：已接入实时扫码、Android/iOS 相机权限、七种语言权限提示和拍照/相册降级；扫码文本继续通过 `newRemoteClient` 校验。无头测试覆盖成功、取消、权限错误、坏链接、无相机及拍照识码。
- **当前验证与剩余项**：`go tool nsgo check` 和短测试通过（639 通过、0 失败、55 跳过）；Web Brotli 为 9.2 MB，低于 12 MB 预算；`android_arm64` 构建通过。Android/iOS 真机相机与权限提示仍需正式验收。

### 3. 自动更新显示版本说明：小改动，可选

- **现状**：`.github/workflows/release.yml` 已构建 appcast 并生成 GitHub Release 文案，但 build 步骤没有传版本说明。
- **SDK 已具备**：`nsgo build -release-notes <Markdown文件>` 可将说明带入 appcast，并由系统更新窗口显示。
- **最小改动**：发布时先准备同一份明确版本的 Markdown 说明，再传给 SDK；保留现有 stable/dev 渠道、签名和应用身份。
- **收益与范围**：用户安装前能看到改了什么，不涉及运行期业务代码。不自动把整份路线图或历史验收日志当作版本说明，也不在本轮启动发布。

## 有接口，但现在不值得批量改

| 项目 | 判断与保留理由 |
| --- | --- |
| 全部对话框迁到 `Leading` / `Trailing` | 新接口适合窄屏里固定的取消/完成操作；现有 Footer 已支持桌面与触屏。没有具体遮挡问题时，批量迁移主要改变操作位置，没有明确功能收益 |
| 聊天面板全部换成官方 `FloatingConversation` | 当前 SDK 已有 `ContentWidth`，但 V2 的不透明输入卡、百分比行宽、待办/目标/信任条、定位轴与历史窗口仍有自己的要求。换控件会牵动滚动、焦点和键盘行为，不是单纯删重复代码 |
| 模型菜单全面换成 `OptionsFunc` | `ui_settings_models.go` 目前通过父级 Dynamic 重建选项；新版能原位更新并保留焦点。只有确认动态更新导致焦点或弹层丢失时再做局部回归和迁移，不把静态语言等菜单一并改造；选项回调不能读磁盘 |
| Windows 会话链接兼容逻辑 | SDK 现在通过 `OnOpenLinks` 支持冷启动与第二实例；`session_links.go` 的 argv / OnOpenFiles 兜底是清理候选。应先验证冷启动、已运行、便携版与 stable/dev，再删兜底。手动注册链接仍对便携版有用途，不能一起删 |
| 内置浏览器 Cookie、UA 和手机模拟 | 已有 WebView 导航、缩放与审批链路继续使用。自动导入 Cookie 会改变当前 `Incognito: true` 的会话策略；手机模拟也改变站点布局和触摸行为，都不是默认收益 |
| Toast、Scroll、Tab 的新样式与动作 | 仅在具体布局、焦点或通知可点击需求出现时使用，不为接入接口增加选项或重做全局样式 |
| 声明式插件换成 TSX 执行型插件 | V2 生产代码仍运行 v2 声明式清单，TSX 仅有测试示例。新 SDK 的预算和生命周期能力有助于后续宿主设计，但没有自动完成权限、分发、撤销、升级和卸载契约 |
| 会话、配置、远程协议与备份 | 本次 SDK 升级没有要求迁移它们。保持现有事实来源、原子写入、版本与格式；不重构存储和后端投影 |
