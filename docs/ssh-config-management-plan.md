| 能力 | 本机现状 | 本次 SSH 交付 |

| PiDeck 随包资源、宿主安全策略 | PiDeck 本机资源 | 按能力隐藏本机专用面板，不把本机资源显示成远端安装 |
| OAuth 登录 | 本机 pi-auth 侧车 | 保持远端终端登录，不回传/编辑 OAuth token |

本次配置环境面板管理的是**所选主机全局资源**。项目右键资源管理仍以已登记的项目身份与信任边界为准；不把项目路径或本机项目当成 SSH 全局资源的替代来源，不扩大项目资源读写权限。

## 契约与边界

1. 认证使用既有 helper 控制连接内的专属动作，不把 `auth.json` 加入通用配置读写白名单。读取只回 provider/type/configured；版本化替换声明保留来源或新 API key，旧凭据与未知字段留在主机。主进程严格复验结果，不输出凭据到日志或错误。
2. 资源使用同一内容寻址 helper bundle 的独立资源域，目录为明确枚举的固定用户资源根。资源引用必须验证根、相对路径、符号链接、文件类型、大小与遍历预算，不提供任意文件路径、shell 或代码执行入口。
3. 写入按读入版本保护，文件保存使用临时文件原子替换并读回确认。删除先在 UI 确认，远端文件移入受控回收目录；版本冲突、断线或回执不可信均保留草稿，不自动重放写操作。
4. Pi 包操作仅接受白名单动作和有界合法包源，由主进程选定该主机已探测的 Node/Pi；固定 argv、固定工作目录、超时与输出脱敏，不接受 renderer 提供命令。失败可见，不回落本机。
5. `PiResourceTarget` 增加 SSH 分支；所有相关 IPC/preload/消费点同步携带目标。界面深层的商店、更新、正文编辑和发现列表也使用绑定目标的 API，禁止绕过适配器调用本机 singleton。
6. 每个主机的读入版本、草稿、请求代数及缓存独立；环境切换、源文件切换和关闭沿用统一未保存确认。保存失败不强制重读覆盖草稿。

## 实施顺序与门禁

1. 先更新宿主边界，再实现专属认证写操作和共享表单/源文件路由。
2. 实现固定资源域与主进程适配器，接入技能/提示词 CRUD、正文保存和原生启停规则。
3. 接入远端 Pi 包操作、扩展列表/管理与商店目标；按能力隐藏本机专用操作。
4. 以冻结 helper、主进程边界和实际 renderer API 为对象写行为测试：主机隔离、密钥不回传、旧版本拒写、路径逃逸/链接拒绝、失败保留草稿、本机/WSL 回归。
5. 运行 `npm run typecheck`、相关定向单测、IPC 接线/格式/文件大小门禁；只构建 main/preload/renderer 涉及的子目标，以隔离 Electron 测试验收共享交互。真实 SSH 连接验收需使用用户已授权的验收主机，本次不自动连接未知外部系统。
